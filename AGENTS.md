# Agent Router

AI assistants should load skills from `.agents/skills/` based on task context.
That directory is generated by `pnpm sync:skills`, which restores shared skills
from `skills-lock.json` and overlays repo-local skills from
`.local-agent-skills/skills/`.

Do not hand-edit `.agents/skills/`, `.claude/skills/`, or `skills-lock.json`.
Edit local skills in `.local-agent-skills/skills/`, then run
`pnpm sync:skills`. Set `SKIP_SKILL_SYNC=1` to skip the postinstall sync path.

CI should configure git auth for `https://github.com/OMGWINNING/internal-skills`
before install so postinstall can validate the committed `skills-lock.json`.

## Project Context

This repository is the Alchemy developer tools monorepo:

- `apps/cli` contains the published `@alchemy/cli` package.
- `apps/mcp-server` contains the hosted Alchemy MCP server.
- `helm` contains the remote MCP server deployment charts.
- `docs` contains architecture and service docs.

Use pnpm from the repository root for workspace operations.

## Available Skills

**Shared DX Baseline:**

- `git`
- `code-review`
- `lsp-setup`
- `typescript`
- `validation`

**Shared AX Skills:**

- `cli` - CLI command structure, output, errors, configuration, and
  distribution guidance
- `build-mcp` - MCP server design, security, tool design, testing, and
  discoverability guidance

**Repo-Local Skills:**

- `changeset` - Create a changeset file for pending user-facing changes
- `add-tool` - Add Alchemy API methods as dedicated MCP tools
- `deploy` - Version bump and deploy flow for the hosted MCP server

## Skill Loading

- Designing or reviewing CLI commands, flags, output, config, help, or install
  behavior -> load `cli`
- Designing or reviewing MCP tools, prompts, resources, transports, or auth ->
  load `build-mcp`
- Adding a new Alchemy API method/tool -> load `add-tool`
- Deploying or bumping MCP server versions -> load `deploy`
- Writing TypeScript -> load `typescript`
- Adding or reviewing validation schemas -> load `validation`
- Setting up LSP or code intelligence for an agent -> load `lsp-setup`
- Reviewing a PR/diff for release safety -> load `code-review`
- Working with PR descriptions or lockfile conflicts -> load `git`

## CLI Styling Guidelines

Prefer shared style helpers in `apps/cli/src/lib/ui.ts`,
`apps/cli/src/lib/output.ts`, and `apps/cli/src/lib/error-format.ts` over
ad-hoc ANSI strings. Keep terminal copy short and actionable.

Human TTY mode may use ANSI styling. `--json` mode must emit valid JSON only.
Respect `NO_COLOR` and avoid terminal-only styling when stdout/stderr is not a
TTY.

All application errors should flow through shared formatters. Commander
parse/usage errors should use `formatCommanderError()`, and application errors
should use `printError()`.

## MCP Guidelines

Prefer dedicated MCP tools with explicit Zod schemas and concise descriptions
over generic catch-all methods for documented Alchemy APIs. Keep hosted-service
concerns such as Express, Redis, auth, metrics, and Helm deployment isolated to
`apps/mcp-server` and `helm`.
