# Agent Router

AI assistants should load skills from `.agents/skills/` based on the task
context. That directory is generated by `pnpm sync:skills`, which restores
the shared skills recorded in `skills-lock.json` and then applies the repo-local
overlays in `.local-agent-skills/skills/`.

Do not hand-edit `.agents/skills/` or `.claude/skills/`. Edit local skills in
`.local-agent-skills/skills/` and re-run `pnpm sync:skills`.
Do not hand-edit `skills-lock.json`; update it with `npx skills add ...` or
`pnpm update:skills` and commit the result.

The postinstall hook attempts to restore shared skills when GitHub auth can
access `OMGWINNING/internal-skills`. Set `SKIP_SKILL_SYNC=1` to skip that local
sync path.

CI should configure git auth for `https://github.com/OMGWINNING/internal-skills`
before install so the postinstall skill restore can validate the committed
`skills-lock.json`.

## Skills Structure

Each skill has:

- `SKILL.md` - Index with description and rule links
- `rules/*.md` - Individual rule files

## Available Skills

**Shared DX Baseline:**

- `git`
- `code-review`
- `lsp-setup`
- `typescript`
- `validation`

**Shared AX Skills:**

- `build-mcp` - MCP server design, security, tool design, testing, and
  discoverability guidance

**Alchemy MCP Server Local Skills:**

- `add-tool` - Add Alchemy API methods as dedicated MCP tools
- `deploy` - Version bump and deploy flow for staging and production

## Skill Loading

Skills are loaded based on the task context:

- Designing or reviewing MCP tools, prompts, resources, transports, or auth ->
  load `build-mcp`
- Adding a new Alchemy API method/tool -> load `add-tool`
- Deploying or bumping MCP server versions -> load `deploy`
- Writing TypeScript -> load `typescript`
- Adding or reviewing validation schemas -> load `validation`
- Setting up LSP or code intelligence for an agent -> load `lsp-setup`
- Reviewing a PR/diff for release safety -> load `code-review`
- Working with PR descriptions or lockfile conflicts -> load `git`

## Project Context

This repo contains the hosted Alchemy MCP server. It uses TypeScript, Express,
the MCP SDK, and Zod schemas. Prefer dedicated MCP tools with explicit schemas
and concise descriptions over generic catch-all methods for documented Alchemy
APIs.
